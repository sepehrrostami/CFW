# Edge Relay

یک رله سبک WebSocket-to-TCP که برای Cloudflare Workers ساخته شده، همراه با یک صفحه‌ی داخلی برای ساخت و اشتراک‌گذاری پروفایل اتصال (شامل کد QR).

**[English version of this guide → README.md](./README.md)**

## شامل چه چیزهایی می‌شه

- `src/worker.js` — خود رله، که به‌عنوان یک Cloudflare Worker دیپلوی میشه
- مسیر `/panel` — یک صفحه‌ی داخلی که پروفایل اتصال شما رو به‌صورت کد QR قابل‌اسکن و لینک قابل‌کپی نشون میده
- مسیر `/links` — همون پروفایل به‌صورت متن ساده، برای اسکریپت‌نویسی یا کپی دستی

هیچ دیتابیس، بک‌اند جدا، یا سروری برای نگه‌داری لازم نیست، و — همون‌طور که پایین‌تر می‌بینید — **هیچ ترمینال یا خط فرمانی هم لازم نیست.** همه‌چیز کاملاً از داخل داشبورد Cloudflare و توی مرورگر قابل انجامه.

## چه چیزی لازم دارید

- یک حساب Cloudflare (پلن رایگان کافیه) — اگه ندارید، توی [dash.cloudflare.com](https://dash.cloudflare.com) ثبت‌نام کنید
- محتوای فایل `src/worker.js` از همین مخزن (توی گیت‌هاب بازش کنید و کل محتوا رو کپی کنید، یا فایل رو دانلود کنید)

همین. برای این روش نیازی به Node.js، npm، Wrangler یا git نیست.

## دیپلوی از داخل داشبورد

### قدم ۱ — ساخت Worker

۱. وارد [dash.cloudflare.com](https://dash.cloudflare.com) بشید.
۲. توی نوار کناری سمت چپ، **Workers & Pages** رو انتخاب کنید.
۳. **Create application** رو بزنید.
۴. قالب **"Hello World"** رو انتخاب کنید و یه اسم براش بذارید (این اسم بخشی از آدرس نهاییتون میشه، مثلاً `my-relay.<your-subdomain>.workers.dev`).
۵. **Deploy** رو بزنید.

### قدم ۲ — جای‌گذاری کد

۱. بعد از این‌که نسخه‌ی placeholder دیپلوی شد، **Edit code** رو بزنید. این یه ادیتور کد آنلاین توی همون مرورگرتون باز می‌کنه.
۲. کل کد placeholder موجود رو انتخاب و پاک کنید.
۳. کل محتوای فایل `src/worker.js` از همین مخزن رو جای‌گذاری کنید.
۴. قبل از دیپلوی، این خط رو نزدیک بالای فایل پیدا کنید و رمز رو به هرچی دوست دارید تغییر بدید:
   ```js
   let plainPassword = 'ygsyafgGGFud123';
   ```
   **فقط همین یک خط رو باید تغییر بدید.** مقداری که واقعاً برای اعتبارسنجی اتصال‌های ورودی استفاده میشه، به‌صورت خودکار از همین مقدار محاسبه میشه، پس چیز دیگه‌ای برای هماهنگ‌کردن نیست.
۵. **Deploy** رو بزنید (معمولاً بالا-راست ادیتور) تا تغییرات منتشر بشه.

### قدم ۳ — دریافت پروفایل اتصال

این آدرس رو توی هر مرورگری باز کنید:

```
https://<your-worker-name>.<your-subdomain>.workers.dev/panel
```

فوراً یه کد QR و یه لینک قابل‌کپی می‌بینید — هیچ تنظیم دیگه‌ای لازم نیست. لینک متنی به‌تنهایی هم از مسیر `/links` در دسترسه.

### قدم ۴ (اختیاری) — تنظیم یک آدرس جایگزین ترجیحی

بعضی مقصدها با اتصال مستقیم قابل‌دسترسی نیستن (به بخش «محدودیت‌های شناخته‌شده» پایین‌تر مراجعه کنید)، پس رله خودکار چندتا آدرس جایگزین رو امتحان می‌کنه. اگه ترجیح می‌دید از آدرسی که خودتون کنترلش می‌کنید استفاده کنید:

۱. به صفحه Worker خودتون توی داشبورد برید ← تب **Settings** ← **Variables and Secrets**.
۲. **Add** رو بزنید ← نوع رو **Secret**، نام رو `PROXYIP`، و مقدار رو آدرس جایگزین خودتون بذارید.
۳. **Save and deploy** رو بزنید.

اگه این قدم رو رد کنید، لیست پیش‌فرض داخل `src/worker.js` (آرایه `h2`) استفاده میشه — دلیل این‌که این لیست همیشه در دسترس تضمین‌شده نیست رو توی بخش محدودیت‌ها ببینید.

## مرجع تنظیمات

لینک/QR تولیدشده شامل موارد زیره:

| فیلد | مقدار | توضیح |
|---|---|---|
| آدرس | دامنه Worker شما | خودکار از درخواست ورودی خونده میشه، نیازی به وارد کردن دستی نیست |
| پورت | ۴۴۳ | ثابت |
| رمز | مقدار `plainPassword` | به‌صورت متن ساده فرستاده میشه؛ کلاینت قبل از استفاده هشش می‌کنه |
| انتقال | WebSocket | |
| TLS | فعال | اثر انگشت `fp=chrome` |
| داده زودهنگام | تا ۲۵۶۰ بایت | داخل هدر `Sec-WebSocket-Protocol` حمل میشه |

## محدودیت‌های شناخته‌شده

- **مقصدهایی که پشت شبکه خود Cloudflare هستن، با اتصال مستقیم قابل‌دسترسی نیستن.** Workerها اجازه ندارن مستقیماً به رنج IP خود Cloudflare سوکت TCP باز کنن — این یه محدودیت سطح پلتفرمه، نه باگ توی این کد. رله در این حالت خودکار به آدرس‌های داخل `h2` سوییچ می‌کنه.
- **آدرس‌های جایگزین پیش‌فرض community-run هستن و ممکنه بدون اطلاع قبلی از دسترس خارج بشن.** برای هرچیزی که بهش وابسته‌اید، آدرس اختصاصی خودتون رو از طریق متغیر `PROXYIP` تنظیم کنید (قدم ۴ بالا).
- اگه یه مقصد خاص مدام شکست می‌خوره، صفحه Worker خودتون توی داشبورد رو باز کنید ← تب **Logs** ← **Begin log stream**، بعد مشکل رو تکرار کنید. رله هر تلاش اتصال رو لاگ می‌کنه، شامل اینکه کدوم آدرس‌های جایگزین امتحان شدن و هرکدوم چرا شکست خوردن.

## روش جایگزین: دیپلوی از ترمینال

اگه ترجیح می‌دید به‌جای داشبورد، به‌صورت محلی با git و Wrangler CLI کار کنید، همین مخزن فایل‌های `wrangler.jsonc`، `package.json` و `.gitignore` رو هم برای این روش داره:

```bash
git clone <your-repo-url>
cd edge-relay
npm install
npx wrangler login
npx wrangler deploy
```

هر دو روش دقیقاً همون کد رو دیپلوی می‌کنن — هرکدوم که راحت‌ترید استفاده کنید.
